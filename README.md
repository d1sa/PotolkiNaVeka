# Potolki Na Veka Landing

Статический SEO-лендинг без внешних runtime-зависимостей. Сайт собирается в `dist/index.html`, чтобы поисковые роботы получали готовый HTML с текстами, а не пустой клиентский шаблон.

## Правило SEO-текста

Файл `src/data/landingContent.js` является единственным местом для утверждённых SEO-текстов. Тексты нужно переносить из ТЗ дословно: без переписывания, сокращения, расширения, исправления, перевода или оптимизации.

В текущем окружении IDE-attachments с `pasted-text.txt` недоступны, поэтому контентные поля оставлены пустыми намеренно. Это безопаснее, чем создавать или заменять отсутствующий финальный текст.

## Запуск

```bash
npm run build
npm run check:content
npm run check:seo-source
npm run start
```

После получения доступного ТЗ заполните только `src/data/landingContent.js`, затем снова выполните сборку и проверку.


## Проверка источника SEO

Когда `SEO.md` станет доступен в рабочем дереве, положите его в `briefs/SEO.md` без редактирования. Скрипт `npm run check:seo-source` проверит, что каждая непустая строка из `src/data/landingContent.js` дословно присутствует в исходном SEO-документе. Для строгого режима в CI используйте `REQUIRE_SEO_SOURCE=1 npm run check:seo-source`.

## Роли агентов

- Архитектор контролирует неизменность SEO-текста и структуру данных.
- UX-агент определяет порядок блоков без переписывания текстов.
- UI-агент работает только со стилями и визуальной иерархией.
- Верстальщик переносит строки из `src/data/landingContent.js` механически.
- QA-агент запускает `npm run check` и сверяет источник `briefs/SEO.md`.
